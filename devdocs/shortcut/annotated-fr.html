Run Img2Video in a-Shell
14 actions · reçoit un dictionnaire { filename, cmd } depuis la feuille de partage, garantit que l’image est présente sur disque, puis lance la commande dans a-Shell Mini.

Le problème que ce raccourci résout

a-Shell ne peut lire que des fichiers présents dans son propre espace File Provider Storage. Une image qui vit uniquement dans la photothèque iOS lui est invisible.

Le raccourci vérifie donc d’abord si le fichier demandé est déjà sur disque. Si oui, il ne fait rien. Sinon, il va le chercher dans Photos et l’y écrit — puis, dans les deux cas, il exécute la commande sur un chemin qui existe forcément.

7 · cœur de la logique

Le fichier ouvert est-il bien celui demandé ?

Deux égalités combinées en ET :

trimmedFilename == Inputfile.Nom
TrimmedExr == Inputfile.Extension

Pourquoi ça marche : si le fichier existe, ces propriétés décrivent le fichier lui-même et les deux tests passent. S’il est absent, elles décrivent le dossier parent — dont le nom est File Provider Storage et l’extension vide — et les deux tests échouent.

Aucune constante en dur : le test se répare tout seul si le dossier cible change.

Branche vraie vide et c’est voulu — le fichier est là, il n’y a rien à faire.

13

Assemblage de la ligne de commande

CmdText + espace + chemin + filename, en une seule action.

Les espaces du chemin sont échappés par \. Les guillemets ne conviennent pas ici : a-Shell les traiterait littéralement, et ils empêcheraient l’expansion du ~.

Limite connue : filename n’est pas échappé. Un espace ou une apostrophe dans le nom casserait la commande — sans conséquence en pratique, les noms issus de la photothèque étant du type IMG_1234.HEIC.

14 · sortie

Exécution

Deux commandes successives. Le cd positionne le répertoire de travail — utile pour les fichiers produits en sortie — puis CMDfinal s’exécute.

Le chemin apparaît dans les deux, sans conflit : ~File\ Provider\ Storage/ est un alias qui résout toujours en absolu, le cd n’affecte donc pas la résolution de l’argument.

Résumé de la logique

Invariant garanti à la sortie du conditionnel : le fichier nommé filename existe dans File Provider Storage.

Comment il est établi : on tente l’ouverture, on vérifie que ce qu’on a ouvert porte bien le nom et l’extension demandés, et si ce n’est pas le cas on va chercher l’image dans Photos pour l’écrire à cet emplacement.

Astuce centrale : l’échec d’ouverture ne se détecte pas par une valeur vide mais par le fait qu’iOS renvoie alors les propriétés du dossier parent — d’où la comparaison nom + extension plutôt qu’un test de nullité.
